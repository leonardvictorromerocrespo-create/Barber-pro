# Instrucciones del proyecto MERYO

- No usar Docker. No iniciar Docker Desktop ni crear, arrancar o ejecutar contenedores para este proyecto. Restricción explícita del propietario del 24 de octubre de 2026 por consumo de recursos/costos; se mantiene en futuras sesiones salvo revocación explícita.
- Para pruebas de base de datos, usar PostgreSQL nativo con instancia y datos exclusivos del proyecto, o un entorno de staging separado. Detener la instancia local de pruebas al terminar. No tocar otros proyectos ni borrar sus datos.
- Nunca usar producción para probar. No desplegar, aplicar migraciones a producción ni habilitar cobros sin demostrar el flujo real en staging y obtener autorización explícita.
- Conservar el diseño y los avances existentes. Consultar docs/MERYO-estado-2026-10-24.md antes de repetir verificaciones.
- El SQL en db/candidate es un esquema candidato local; no representa el esquema existente de Supabase. Contrastarlo con el export real antes de integrar.
- No exponer ni registrar secretos. Modelo vigente: mensualidad por barbería, sin comisión MERYO por corte. Conservar historial previo; precios de planes propuestos, sin activar suscripciones. No implementar reparto de fondos sin validar al proveedor.
- Plazos aprobados: 15 minutos para aceptación manual y 10 minutos para pagar el adelanto del 50 %, siempre desde el servidor. Ningún pago simulado confirma una cita comercial.
- Google OAuth local está configurado fuera de Git. Los roles vienen de profiles y administración exige MFA real/AAL2 en SQL. Nunca generar administradores desde metadatos de registro.
- Respaldo externo alojado verificado el 27 de octubre de 2026: workflow existente de GitHub Actions, Google Drive privado, cifrado, programación 03:17 Lima, conservación 30 días y límite de seguridad 250 MiB por copia. Dos ejecuciones descargaron y restauraron la copia independiente sin servicios de la PC. Consultar docs/MERYO-storage-real-2026-10-27.md antes de repetirlo. Storage de producción estaba vacío; no afirmar que se restauraron archivos de clientes inexistentes. No prometer pérdida cero, cuota ilimitada ni puntualidad garantizada del scheduler. La clave de recuperación permanece fuera de Git y separada de Drive.
